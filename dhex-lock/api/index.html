API reference

Getting started

The API is on from the start and can be turned off under Remote control (API) in the admin menu. That screen shows the device's address, the port (2323 unless you choose another) and the access key, which is created automatically. The API only answers while kiosk mode is active.

Security

  • Every request needs the access key. Without it the API answers 401.
  • The traffic is unencrypted HTTP. Only use the API on a network you trust, and never expose the port to the internet. Anyone with the key can control the device and take photos with the camera.
  • The key is not included in an exported configuration. Create a new access key makes the old one invalid immediately.

Send the key in one of three ways:

Authorization: Bearer <key>
X-Api-Key: <key>
...?token=<key>

Endpoints

Commands that change something need POST (PUT for the configuration). Parameters can be sent in the query string, as a form or as a JSON body. Answers are JSON: successful commands return {"ok":true} and errors return {"ok":false,"error":"..."} with a matching status code.

MethodPathParametersDoes
GET/api/statusDevice state, see below
POST/api/screen/offTurns the screen off
POST/api/screen/onTurns the screen on and brings the kiosk to the front
POST/api/web/loadurlLoads a page in web mode
POST/api/web/reloadReloads the page
POST/api/web/homeGoes to the start URL
POST/api/modemode = web, app or mediaChanges content mode
POST/api/brightnesspercent = 1–100 or systemSets the brightness
POST/api/volumepercent = 0–100Sets the volume
GET/api/camera/photocamera = front or back (optional)Takes a photo, answers with image/jpeg
GET/api/motionState of motion detection
GET/api/configThe whole configuration as JSON
PUT/api/configbody: configuration as JSONReplaces the configuration
POST/api/rebootRestarts the device

Status codes: 200 success, 400 wrong or missing parameter, 401 wrong key, 404 unknown path, 405 wrong method, 409 not possible in the current mode (for example a web command when web mode is not active), 413 request too large, 503 camera not available.

Examples

KEY=your-key
HOST=http://192.168.1.50:2323

curl -H "Authorization: Bearer $KEY" $HOST/api/status
curl -H "Authorization: Bearer $KEY" -X POST $HOST/api/screen/off
curl -H "Authorization: Bearer $KEY" -X POST "$HOST/api/web/load?url=https://example.com/menu"
curl -H "Authorization: Bearer $KEY" -X POST "$HOST/api/brightness?percent=40"
curl -H "Authorization: Bearer $KEY" -o photo.jpg "$HOST/api/camera/photo?camera=front"
curl -H "Authorization: Bearer $KEY" $HOST/api/config > config.json
curl -H "Authorization: Bearer $KEY" -X PUT --data-binary @config.json $HOST/api/config

  • brightnessPercent and volumePercent are the configured values; -1 means the system controls the brightness, or that the volume is left alone.
  • scheduledScreenOn tells what the screen schedule says right now.
  • web.url is null when web mode is not shown.
  • secondsSinceMotion is null until the first motion has been detected.

Good to know

  • /api/web/load may show an address outside the list of allowed domains, but further navigation from that page follows the list. Add the domain to the list if users should be able to click on.
  • /api/brightness, /api/volume and /api/mode change the configuration and therefore remain after a restart.
  • /api/mode answers 409 if the mode cannot be turned on, for example if no app is chosen for Single app.
  • /api/reboot requires Device Owner.
  • Photos are at most 1280 pixels wide. The first photo after the camera has been opened takes a second, while the exposure settles.
  • After /api/screen/off, motion detection waits 15 seconds before it may turn the screen on again.

Motion detection

Turned on in the same menu. The camera compares pictures about four times per second. When it detects motion, the screensaver is woken and the inactivity timers are reset, and the screen is turned on if Turn the screen on at motion is on and the screen schedule allows it. Pictures are analysed on the device and are never saved or sent. A picture only leaves the device through /api/camera/photo.

API-beskrivning

Kom igång

API:et är på från början och kan stängas av under Fjärrstyrning (API) i admin-menyn. Skärmen där visar enhetens adress, porten (2323 om inget annat väljs) och åtkomstnyckeln, som skapas automatiskt. API:et svarar bara medan kioskläget är aktivt.

Säkerhet

  • Varje anrop kräver åtkomstnyckeln. Utan nyckel svarar API:et 401.
  • Trafiken är okrypterad HTTP. Använd API:et bara på ett nätverk du litar på, och släpp aldrig ut porten mot internet. Den som har nyckeln kan styra enheten och ta bilder med kameran.
  • Nyckeln följer inte med i en exporterad konfiguration. Skapa ny åtkomstnyckel gör den gamla ogiltig direkt.

Nyckeln skickas på något av tre sätt:

Authorization: Bearer <nyckel>
X-Api-Key: <nyckel>
...?token=<nyckel>

Anrop

Kommandon som ändrar något kräver POST (PUT för konfigurationen). Parametrar kan skickas i frågesträngen, som formulär eller som JSON-kropp. Svaren är JSON: lyckade kommandon ger {"ok":true} och fel ger {"ok":false,"error":"..."} med passande statuskod.

MetodSökvägParametrarGör
GET/api/statusEnhetens läge (exempel i den engelska delen)
POST/api/screen/offSläcker skärmen
POST/api/screen/onTänder skärmen och lyfter fram kiosken
POST/api/web/loadurlLaddar en sida i webbläget
POST/api/web/reloadLaddar om sidan
POST/api/web/homeGår till start-URL
POST/api/modemode = web, app eller mediaByter innehållsläge
POST/api/brightnesspercent = 1–100 eller systemSätter ljusstyrkan
POST/api/volumepercent = 0–100Sätter volymen
GET/api/camera/photocamera = front eller back (valfri)Tar en bild, svarar med image/jpeg
GET/api/motionRörelsedetekteringens läge
GET/api/configHela konfigurationen som JSON
PUT/api/configkropp: konfiguration som JSONErsätter konfigurationen
POST/api/rebootStartar om enheten

Statuskoder: 200 lyckat, 400 fel eller saknad parameter, 401 fel nyckel, 404 okänd sökväg, 405 fel metod, 409 går inte i nuvarande läge (t.ex. webbkommando när webbläget inte är aktivt), 413 för stor förfrågan, 503 kameran går inte att använda.

Exempel och statussvarets format står i den engelska delen; de är desamma.

Att tänka på

  • /api/web/load får visa en adress utanför listan med tillåtna domäner, men vidare navigering från den sidan följer listan. Lägg till domänen i listan om användaren ska kunna klicka sig vidare.
  • /api/brightness, /api/volume och /api/mode ändrar konfigurationen och ligger därför kvar efter omstart.
  • /api/mode svarar 409 om läget inte går att slå på, t.ex. om ingen app är vald för läget En app.
  • /api/reboot kräver Device Owner.
  • Bilder har högst 1280 punkters bredd. Första bilden efter att kameran öppnats tar någon sekund, eftersom exponeringen måste ställa in sig.
  • Efter /api/screen/off väntar rörelsedetekteringen 15 sekunder innan den får tända skärmen igen.

Rörelsedetektering

Slås på under samma meny. Kameran jämför bilder ungefär fyra gånger per sekund. Vid rörelse väcks skärmsläckaren och inaktivitetstiderna nollställs, och skärmen tänds om Tänd skärmen vid rörelse är på och skärmschemat tillåter det. Bilderna analyseras på enheten och sparas eller skickas aldrig. En bild lämnar enheten bara genom /api/camera/photo.
